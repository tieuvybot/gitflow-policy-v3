GitFlow Policy v3

Mandatory branch rules for AI agents — enforced locally.

Provider-agnostic policy for Cursor, Claude Code, Codex, Gemini, and more. AGENTS.md sets the rules; hooks fail early when they are broken.

View on GitHub Install hooks

One promotion path

Work lands on develop first; main stays release-only. 

feature/* ──┐
            ├── PR → develop → PR → main
bugfix/* ──┘

Hard requirements for agents

From AGENTS.md — do not reinterpret, soften, or bypass.

  1. Edit only on feature/* or bugfix/*. Create the branch before the first change.
  2. Commit and push only on work branches — never on main, develop, or detached HEAD.
  3. Never push directly to protected branches.
  4. PR targets: feature/*|bugfix/* → develop, then develop → main.
  5. Never skip hooks with --no-verify or similar bypasses.

Local hooks reinforce the policy

Fail early in the workspace — independent of any AI vendor.

  • pre-commit — blocks commits outside feature/* / bugfix/*
  • pre-push — blocks pushes to main, develop, or other non-work branches
  • post-checkout — warns when you land on a protected branch

Local setup

Run once after cloning. Needs Git (on Windows: Git for Windows + Git Bash). 

./scripts/setup-git-hooks.sh
git config --get core.hooksPath
# Expected: .githooks

Then work as usual on a feature branch, push, and open feature/* → develop. Promote releases with develop → main.
